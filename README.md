# BARBER HOUSE — Telegram Mini App + Render + Neon

## Architecture
- Telegram bot: grammY, webhook через тот же Render Web Service.
- Mini App/API: Node 22 HTTP server, hosted on Render.
- Database: Neon PostgreSQL.
- Bot and Mini App use the same booking functions and database.

## Deploy
1. Create a Neon PostgreSQL project and copy its pooled `DATABASE_URL`.
2. Create a Render Blueprint/Web Service from this repository. `render.yaml` is included.
3. Set `BOT_TOKEN`, `DATABASE_URL`, `TZ_NAME=Europe/Moscow`. `WEBHOOK_SECRET` is generated by the Blueprint. `WEB_APP_URL` is optional because Render's `RENDER_EXTERNAL_URL` is used automatically.
4. Deploy and open `/health`; it should return `{"ok":true}`.
5. The service initializes the Neon schema and default services/masters on first start and configures the Telegram webhook automatically.
6. In BotFather, set the bot menu button to the Render URL if desired. The bot also shows an inline `📱 Открыть приложение` button automatically.

## Important
- Rotate the Telegram bot token if it was ever included in a shared archive or public repository.
- Never commit `.env`, database passwords, or `barbershop.db`.
- The Mini App validates Telegram `initData` on the server before accessing user bookings or creating/canceling bookings.

## Existing SQLite data
The deployment initializes the Neon schema and default catalog. Existing SQLite bookings are not copied automatically. If you need the current bookings migrated, do that once from a trusted local copy using the migration script/SQL rather than committing the SQLite database to GitHub.
